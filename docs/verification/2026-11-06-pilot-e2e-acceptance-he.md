- בדיקות ספק האימות: 3/3; בדיקות ממוקדות אחרונות לפרסום ול־workflow: 13/13; TypeScript ובניית standalone עברו.
- רגרסיית `runtime-smoke.mjs` עברה בהרצה מבודדת. ניסיון מקביל תחת עומס נכשל ב־503 באימות ספק סינתטי; הכשל לא שוחזר בהרצה המבודדת וסווג תפעולית כמגבלת runner/סביבה. הקשר לעומס הוא השערה, ולא בוצע שינוי timeout או מדיניות אימות.
- ניסיונות בתוך הסנדבוקס נחסמו ב־spawn EPERM בבנייה/תהליכי בדיקה. הורצו מחדש עם הרשאה לתהליכים המקומיים. ניסיון חבילה ללא process isolation נקטע ולא נספר כמעבר.
- הרצות קבלה #14–#21 נכשלו: #14 ו־#21 הוכיחו פגמי אפליקציה; #15/#16 סדר פתיחת disclosures ב־fixture; #17 MIME של worker PDF וסדר אישור; #18 ציפייה ל־403 במקום חוזה 404 של משאב זר; #19 פרשנות שגויה של הערת צוות; #20 הגדרת Calendar סינתטי חסרה. #22 עברה את תיקון המזכירה ואת זרימת Calendar ונכשלה ב־selector שגוי של היסטוריית התורים. כל הכשלים נשמרו ונותחו; לא הוסרו assertions כדי לקבל ירוק.
- סיכום ניסיונות הקבלה בהמשך זה (#14–#28): הרצה ממוקדת מוצלחת אחת (#28); 13 הרצות שנכשלו; הרצה אחת (#25) הסתיימה ללא דוח סיום בגבול חידוש השיחה ולכן אינה מעבר. #23 נכשל בהקדמת בדיקת שפה ל־hydration וב־teardown; #24 ו־#27 נכשלו על מיפויי נוסח אנגלי ב־fixture; #26 נכשל בהפעלת Chromium. אלו תוקנו או סווגו כמגבלות סביבה, בלי הסרת assertions. כל ששת מסעות העברית הושלמו גם ב־#23 וגם ב־#24.
- הספק הסינתטי חוסם יעדי יציאה לא מורשים. ייחוד OTP/סשן חדש נבדקים במסע הקבלה ובבדיקות הספק; איפוס חלון resend מתבצע רק במסד המקומי, לאחר הוכחת 429, כדי לא להוסיף המתנות זמן אמיתי.

## שחזור

מתוך `apps/doctorcoach-standalone`, עם Node 24.22.2 ו־Chromium/Chrome מותקן:

```sh
pnpm install --frozen-lockfile
npm run typecheck
npm test
npm run build:standalone
node --test tests/synthetic-auth-provider.test.mjs
DC_CHROMIUM=/usr/bin/google-chrome node --experimental-strip-types standalone/scripts/pilot-acceptance.mjs
node --experimental-strip-types standalone/scripts/runtime-smoke.mjs
```

ב־PowerShell יש להגדיר `$env:DC_CHROMIUM='C:/Program Files/Google/Chrome/Application/chrome.exe'` ואז להריץ את אותה פקודת Node. אפשר לשנות תיקיית ראיות באמצעות `DC_PILOT_EVIDENCE`. אבחון ממוקד בשפה אחת אפשרי באמצעות `DC_PILOT_LANGUAGE=en` או `he`; ברירת המחדל וה־CI דורשות את שתי התצורות. אין להריץ כמה מופעי קבלה לאותה תיקיית ראיות במקביל.

ה־workflow החדש `pilot-acceptance.yml` נפרד מהחבילות היקרות הקיימות, עם מגבלה של 20 דקות ו־artifact מסונן. הוא רץ על push לענף הפיילוט ועל PR לאינטגרציה, ורושם checkout SHA, tree ו־PR head. ב־pull_request ה־checkout הוא synthetic merge; ב־push הוא ראש הענף. אין להציג את שניהם כאותו checkout רק משום שמקורם באותו PR.
