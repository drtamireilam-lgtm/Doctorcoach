# Anatomy LAB follow-up QA — 2026-10-18

## Scope

Only feature/interactive-3d-anatomy. Existing Production, navigation, training and databases unchanged. No deploy or merge into another branch. Local duplicate commit history was reconciled with the previously verified remote branch before edits.

## Source-level defects fixed

1. Malformed percent-encoded hash could throw during initial render/history navigation. Safe decoding now falls back to pectoralis-major; unknown/empty IDs do the same.
2. A direct URL to a deep muscle or history navigation selected the information panel while leaving its mesh layer hidden. Initial selection and history changes now reveal its layer. User can still manually hide any layer.
3. Front/back controls previously reset distance to 5.8, losing zoom. They now retain the current camera-target distance.
4. Zoom buttons previously used an absolute counter, causing a jump after a pinch/wheel gesture. Each step now adjusts from current camera distance, within OrbitControls' 3–10 bounds.
5. Dragging could trigger muscle selection. Mesh selection now ignores pointer travel greater than four pixels.
6. Repeated selection no longer adds duplicate hash history entries. Both hashchange and popstate synchronize selection.
7. Added a keyboard skip control and a focusable detail panel with a direct jump control, useful when the mobile list precedes details. These use focus rather than conflicting muscle URL hashes. Canvas has a text alternative description; play state is exposed via aria-pressed.
8. Clarified that selection is gold only while its layer is shown and other layers may occlude it.

## Automated verification

Anatomy regression suite now checks all 15 deep links, encoded and malformed hashes, unknown/empty IDs, zoom bounds and relative zoom, click/drag threshold, and CPU Three.js ray intersection against every muscle's proxy volume. Existing checks cover IDs, content presence, valid exercise links/roles and abduction angle bounds. Anatomy suite is included in `npm test` for future CI.

**CPU raycasting is not browser picking validation.** These checks do not validate the React event wiring, OrbitControls gestures or visible render.
