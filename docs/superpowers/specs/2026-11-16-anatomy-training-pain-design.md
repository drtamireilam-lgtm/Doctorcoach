# Anatomy, training and private pain map

Approved scope: all three user-approved steps, executed without another approval gate. Reuse the existing exercise relationships, program API, consent and account-deletion path. No Production deployment.

1. Exercise → detailed atlas: highlight existing primary/secondary/stabilizer/stretch relationships; show a labelled legend and available/missing relationships. Links from the library and active workout open that exercise context. Never infer activation by name. Preserve ordinary atlas navigation.
2. Anatomy → exercise → program: retain exercise details and add an explicit workout-day selector using the current controller and permission checks. Save one new occurrence to the selected day, preserve existing doses/history, show actual success/error. Coached trainees cannot alter assigned programs.
3. Pain: dedicated private owner-only endpoint storing append-only reports in existing wellness_records with kind=painLocation. Generic wellness bundles exclude these records for everyone. Health consent is checked on read/write, including final/atomic guards. No new migration is required (kind is unconstrained text). Existing account deletion covers this table. Data: model checksum, source mesh reference, normalized XYZ in centered whole-model bounds, explicit view and side, intensity integer 0–10, occurredAt UTC, before/after/other timing, bounded note, optional visible exercise reference. A mesh is a location reference, never a diagnosis. Default visibility is owner-only; no care role/admin/feedback access.

Separate pain UI owns its 3D scene and in-memory draft; no health draft/marker/camera in URL, session/local storage, analytics or logs. Pointer raycast returns a surface point after actual orbit/pan/zoom; keyboard alternative places at the explicitly named mesh centre and labels it approximate. Marker is a world-space point, retained on view changes. History loads from server; retry reuses the same report ID; future/invalid dates, invalid coordinates/model/structure/side/exercise rejected. Account identity gates the UI and remounts it; auth failure hides stale history. Failed save retains draft in memory and must not claim success.

Alternatives: feedback storage rejected (wrong visibility/consent); ordinary shared rehab records rejected (too broad access); new table unnecessary because existing generic records and deletion guards suffice. No medical advice or automatic workout restriction is introduced.
