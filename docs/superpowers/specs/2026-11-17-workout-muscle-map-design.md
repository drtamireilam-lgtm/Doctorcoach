# Workout muscle map
User approved implementing the proposed whole-workout muscle map. Use existing explicit exercise profiles and source geometry. In My Program, a collapsed read-only map lets a signed-in user select a program day or weekly summary, switch to one exercise occurrence, click a model muscle or accessible list, and inspect contributing exercises and planned working sets by primary/assisting/stabilizing role.

One weekly summary means one occurrence of each programmed day, explicitly labelled as that assumption; no calendar frequency exists in ProgramSplit. Counts are planned sets, never completed sets, activation, physiological load, a safety score or a recommendation. A set can count for multiple muscles; role columns must not be summed into a single load. Per-exercise warmupSets, warmup/stretch sections, cardio and stretch roles do not add working-set counts. Unknown/custom and invalid prescriptions are reported, never inferred from names. Repeated exercises remain separate occurrences and changing plans does not change historical session data.

Aggregate surface colour uses the first applicable category primary > secondary > stabilizer, meaning a muscle has that role in at least one included exercise; all role counts remain visible. Deltoid parts retain exact source-specific matching. Missing geometry is reported. Selecting an exercise updates colours in the same renderer; selection and hide controls still work. One lazily opened scene, disposed on collapse/day/scope/account/page changes. No additional scene in active workout to compete with existing pain scenes. The program map uses plan data only, no writes or new schema. The UI is HE/EN, RTL/LTR, responsive320/390/430/768, text-labelled colours, and full list fallback without WebGL. LAB gating stays in place for pending-review3D.

Approach: reuse current AnatomyModelViewer with optional explicit overlay links and a selection callback, plus one pure aggregation module and one isolated program-map component. A separate renderer would duplicate scene lifecycle; navigation through the exercise library would lose the whole-program context. Chosen reuse minimizes GPU and state risks.
