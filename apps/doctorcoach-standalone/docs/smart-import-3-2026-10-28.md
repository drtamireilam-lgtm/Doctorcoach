# Smart Import 3.0 — LAB candidate, 28 October 2026

The real workbook `תוכנית_אימון_RPE.xlsx` was not accessible in attachments or the searched workspaces and has been requested. The real 26-exercise acceptance test is pending. Synthetic fixtures are explicitly labelled and must not be reported as the original program.

Root cause: ProgramExcelImport disabled review/save whenever a row was not matched. importRowItem required a nonempty library ID and parseAssignedItems rejected unknown IDs. No database foreign key required a global library ID: coach drafts and care/workspace programs already persist complete item JSON. The save serializer also stripped custom snapshots, which would break an inline fallback. A single-cell C2 heading was reproducibly extracted as an exercise; without the real workbook this is not proof of its reported 27th row.

Implementation reuses the existing parser, matching index, coach review, guarded drafts, assignment and custom snapshot representation. Unknown and uncertain exercises get a program-scoped `import-...` ID and a minimal server-sanitized custom snapshot. These are never inserted into the global custom_exercises table. Existing real catalog/private custom IDs must still resolve through the authorized catalog. Source provenance is optional on legacy items and strictly bounded/validated on new items.

Provenance: immutable imported name, normalized name, current match status/reference, file name/SHA-256, sheet, source row/cells, day label/order, original sets/reps/weight/RPE/notes/equipment. Current prescriptions remain separate. Active per-set repetitions use setReps; immutable source reps never reactivate after a coach changes dose or unit. Existing targetRpes handles per-set effort. Comma RPE lists use set count and the half-point RPE contract; ambiguous values/ranges stay visible without a guessed scalar. Invalid/out-of-range dosing still blocks. Load metadata and original numerical weights are preserved.

The existing private alias table is reused. Canonically equivalent Unicode/quote variants cannot create duplicate coach aliases, and existing keys remain valid through lookup-on-write. Remembered mappings apply only from the signed-in coach's loaded records and reject explicit qualifier/equipment conflicts. Corrections/deletion and final-statement role guards remain in place. No global aliases or exercise definitions are silently created.

The import save action persists a private coach draft through the existing autosave machine; it does not assign automatically. Explicit review, current-version, pending-draft, overwrite and assignment guards remain. Preview shows matched/review/custom/error counts with an optional filter. The editor supports later library replacement while preserving source data and previous workout snapshots.

Programs with source rows and inline definitions can exceed the prior 64,000-character request limit. Only the four program draft/assignment routes use the new 256,000-character bounded limit; messaging and unrelated endpoints keep existing limits. No schema migration is required. Supabase remains identity/session-only; D1 holds the guarded program data.

A browser regression exposed an invalid PDF worker URL from the previous dynamic ?url import. Static URL asset import fixes this while the PDF parser remains lazy. OCR is not added. See [Vite explicit URL imports](https://vite.dev/guide/assets.html#explicit-url-imports).

Tests cover unknown/ambiguous fallback, C2, per-set and ranged dose, exact weights, immutable source after edits, private aliases, malformed snapshots, cross-user denial, save/reload/assignment, manual results and the bounded large-program request. Browser coverage uses actual ProgramExcelImport with local SQLite-backed synthetic identities, XLSX/CSV/text-PDF and a separately labelled small A/B/C/C2/D fixture in Hebrew/English at 390/1440 widths. The built Worker HTTP runner separately verifies the real draft/assignment/training API paths. Live real-workbook acceptance must remain explicitly pending until the file is supplied.
