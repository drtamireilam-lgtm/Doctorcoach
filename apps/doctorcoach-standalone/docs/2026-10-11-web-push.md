# Web Push

Adds an owner-authenticated device-registration/test/unsubscribe API, Push settings and a fixed generic service-worker notification. iOS users must launch the installed Home Screen app and grant permission by pressing Enable. Registration also requires current notification consent. Up to five devices are owner scoped; endpoints are excluded from API status and client exports. No other account can remove, test or take over a device.

RFC 8292 VAPID uses P-256 WebCrypto. Push requests have no payload, use TTL 0 and disallow redirects; destinations are limited to Apple, Google FCM and Mozilla's supported hosts. The worker displays only a fixed bilingual generic message, without medical data or names. No third-party notification service account is added. The VAPID private JWK is a Sites runtime secret, absent from source and browser bundles.

Deployment inspection identified a Workers-for-Platforms dispatch namespace. Cloudflare does not support native cron triggers there (workers-sdk issue 13840). The unsupported trigger was removed. A custom Worker entry preserves Vinext's fetch handler and uses waitUntil after successful API mutations to dispatch notifications without the recipient opening their app. Time-only reminders remain blocked on a supported external scheduler. Each dispatch scans a rotating bounded page of 50 device registrations, applies current notification consent/categories/dismissals/quiet hours, claims a device to avoid parallel duplicates, checks consent again, sends a generic push and records its fingerprint only when accepted. Invalid 404/410 endpoints are removed; other failures are retried. No unauthenticated dispatch API is exposed. Migration 0020 adds only the device table and owner index.

Test Push is limited to once per minute, obeys consent/quiet hours and reports provider acceptance, not confirmed delivery. Unsubscribe removes server registration first. TTL 0 deliberately prevents queued notifications reaching an offline phone later, reducing stale notification delivery. The cron checks can deliver only when the device is reachable; system Focus/notification settings may suppress presentation.

Ten automated tests cover endpoint validation, JWT signature and empty payload, owner isolation, consent, duplicates/concurrency, quiet hours, expired-device cleanup, test throttling, device limits and consent revocation during dispatch. All 689 tests and TypeScript passed. Deployment verification checks the event-driven dispatcher and confirms no unsupported cron configuration is claimed. Actual provider/device receipt, iPhone permission and background execution still require operational acceptance; no real device was registered or notified in development.
