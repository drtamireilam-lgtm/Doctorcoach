191 extracted rows: baseline #50 matched 95; first #53 candidate matched 100; this follow-up matches 106 (55.5%). All 95 previously assigned rows retain their targets. 85 rows still need review. Do not silently reinterpret these as the nearest current variant. This is a development corpus used for alias curation, not a held-out dataset; 106/191 is automatic coverage, not measured precision/recall.

## Safe feedback export

The existing per-coach import memory persists corrections with owner authorization and explicit save. A new HE/EN download in the importer converts that signed-in coach's persisted corrections into `DoctorCoach-alias-proposals.json`:

- Whitelist source name, builtin target ID, needs-review state and collision diagnostics. Never export account identifiers, version fields, prescriptions or extra object metadata.
- Omit names already recognized for that target and private/custom exercise IDs. Deduplicate normalized source/target pairs; cap input processing at the existing 250-memory limit.
- Flag contradictory qualifiers, existing different targets, ambiguity and conflicting token-equivalent proposals. Every proposal remains `needs_review`; no file is considered approved.
- No network send, shared-dictionary mutation, migration or new remote storage. This is a manual review input, not a central moderator approval/apply service.
- Names are user-provided free text; the interface asks the coach to review them before sharing. Field projection does not prove a source name itself contains no personal text.
- Literal-only matching mode avoids expensive fuzzy ranking for each export entry. Normal importer matching continues to supply fuzzy suggestions for manual review.
