# Independent coach workspaces

Entry point: `/coaching`, linked from account settings. Authenticated users may submit a name, business, specialties and biography. Registration creates a pending workspace and grants no clinic role. Only configured physician owners (`ownerProgramEmails`, the server-side clinician/admin intersection) activate or pause a workspace and allocate a time-limited manual license and plan capacity. Pilot and starter allow 10 active trainees, pro 25, growth 50. Displayed prices are proposed prices; no payment or renewal is executed.

The coach generates a seven-day, email-bound invitation and personally passes the code to the trainee. The server stores only its SHA-256 hash. Preview is available only to the invited authenticated email. Acceptance requires current onboarding/health/team consents plus explicit workspace sharing consent and a deliberately limited training profile (name, goal, experience, equipment, days). Coach approval and patient relationships in clinic tables are never created. One external workspace can be active per trainee; the trainee may revoke it, and the coach may archive/reactivate consenting trainees. Capacity is checked again in SQL at acceptance/reactivation and license downgrade. Archived/revoked members do not consume seats. Revoked profiles are cleared and cannot be restored by the coach.

Programs and drafts are isolated in `workspace_programs` and `workspace_drafts`. The existing builder and Excel/PDF importer use scope-specific endpoints. Active programs have `workspace-<uuid>` IDs, so the existing clinic authorization paths remain unchanged. The ordinary trainee workout UI reads the authorized workspace prescription and rechecks active membership/license inside start and set writes. Finish/cancel remain available after revocation. New prescriptions cannot replace an active workout; revisions are immutable and retries do not reactivate old versions. Coach progress history includes sessions attributed only to this workspace's programs. No medical document, clinic note, intake medical payload, clinic roster, or other coach's client/profile/program is returned from these endpoints.

External workspace authors may create private custom exercises and store their own import mappings while licensed, without becoming clinic staff. Global publication of an exercise remains physician-owner approval. Custom definitions assigned by a workspace are available to that authenticated trainee while the workspace relationship is active.

Migration `0034_coach_workspaces` adds five separate tables. Export includes a user's own workspace profile, own trainee memberships and own assigned programs. Trainee deletion removes scoped membership, draft and program records. Workspace owners follow the protected business/staff deletion process rather than ordinary automatic patient deletion. Browser QA is unavailable in this environment; server integration tests cover authorization, quota, invitations, assignment/drafts, full workouts, private exercises, revocation, expiry and read/write races.

Private workspace conversations were added in migration 0035; see workspace-chat.md.

Not included in this stage: checkout/recurring payment, automatic renewals, coach photo uploads, multiple staff seats per external business, external workspace video feedback, or automatic medical consultation entitlement. These must be added through explicitly scoped workspace capabilities later.
