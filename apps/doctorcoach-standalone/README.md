# DoctorCoach — קוד האתר והאפליקציה להתקנה

מקור הקוד הקובע, ההבדל מול אב־הטיפוס ב־GitHub וסדר העבודה מהאודיט מתועדים ב־[DEVELOPMENT_STATUS.md](./DEVELOPMENT_STATUS.md).

DoctorCoach היא אפליקציית ווב בעברית (RTL), עם תוכנית אימונים אישית, תיק מתאמן, סביבת צוות, סרטונים, תורים ומעקב אימונים. אותה גרסה פועלת בדפדפן ויכולה להיפתח כאפליקציית PWA ממסך הבית, בדפדפנים התומכים בכך.

האתר הנוכחי: https://doctorcoach.dr-tamireilam.chatgpt.site

## מה יש בפרויקט

- עיצוב אדום ושחור עם הלוגו המקורי שאושר: DC, דמות וקו דופק. משולב בתפריט, בכותרת, בפוטר ובאייקוני ההתקנה.
- 63 תרגילים בעברית ובאנגלית, חיפוש וסינון לפי קבוצת שרירים, סוג ורמת קושי.
- מועדפים הנשמרים בחשבון האישי, עם מעבר מהיר בין כל הספרייה לתרגילים שנשמרו.
- שישה אזורי תרגול סביב כאב ומסכי פירוט תרגיל, ובנוסף ״שיקום עמוד השדרה״ עם לשוניות ״צווארי״ ו״גב תחתון״. שתי לשוניות השיקום ריקות מתרגילים ומוכנות להוספת התוכן בהמשך.
- תוכנית אישית עם הוספה, הסרה, סטים, חזרות/שניות/דקות, משקל והערות.
- אימון פעיל עם סימון כל סט, תיעוד ביצוע בפועל, המשך אחרי רענון, Actual RPE וסרטון לכל סט.
- קיצור להמשך האימון הפעיל גם בעת מעבר לספרייה, לתוכנית או למסכים אחרים.
- היסטוריית אימונים מפורטת, גרף כאב מדווח, ייצוא CSV והדפסת תוכנית.
- מסך בית שמציג את התוכנית וההתקדמות וניווט תחתון בטלפון.
- רישום אימונים ונתוני תחושה לפני ואחרי, כולל שמירת הרשומות מהגרסה הקודמת בנפרד.
- צד שרת: API, בדיקת משתמש מחובר, נתונים נפרדים לכל משתמש ומסד D1.
- עמוד ייעוץ וליווי שמציג שירותים, נותן שירות, משך מפגש ומחיר.
- אזור ניהול מוגן להוספת שירותים, עריכת מחירים, שמירת טיוטות וחיבור קישורי אירועים ב־Calendly.
- לוגו ואייקונים להתקנה ב־Android וב־iPhone, manifest, חלון הנחיות התקנה, קיצורי מסך הבית ומסך ללא חיבור.

- שאלון פתיחה עם מטרות, ניסיון, ציוד וחלק רפואי נפרד.
- ניהול צוות ומתאמנים, הזמנה חד־פעמית לשיתוף, הרשאות רופא/מאמן והפסקת שיתוף עצמאית.
- שיוך תוכנית אישית למתאמן, הערות מקצועיות ומענה לדיווחים שבועיים.
- העלאת סרטוני הדגמה בידי הצוות ופרסומם לאחר אישור זכויות; הצגה גם בעמוד התרגיל.
- סרטוני ביצוע פרטיים למשוב מהצוות המשויך, עם הרשאות שנבדקות בכל צפייה.
- בקשות לתור, אישור מועד, בדיקת חפיפה, ביטול ומעקב אחר תשלום והחזר.
- ייצוא מפגש מאושר ליומן עם תזכורות יום ושעה לפני, ותזכורת בתוך האתר ב־24 השעות שלפני.

האתר פועל במחשב ובטלפון באותו קישור ובאותו חשבון. סרטוני הדרכה אמיתיים, קישורי Calendly וקישורי תשלום עדיין דורשים הזנה של הצוות. בקשות באתר מאושרות ידנית; תשלום מתבצע אצל ספק חיצוני ונרשם כמאומת רק לאחר בדיקה ידנית של הצוות. אין סנכרון אוטומטי עם Calendly/ספק הסליקה ואין הודעות SMS או דוא״ל אוטומטיות. מחירים מוצעים ותוכן מקצועי דורשים אישור של נדב ותמיר לפני שימוש עם לקוחות. מסלולי התזונה של ליאור זליקסון מוצגים לחודש, 3, 6 ו־12 חודשים ללא מחיר עד החלטת הצוות. אין כאן קובץ APK/IPA או העלאה לחנויות.

## הרצה במחשב

נדרשים Node.js בגרסה 22.13 ומעלה ו־pnpm בגרסה הרשומה ב־package.json. אפשר להתקין pnpm באמצעות הוראות הספק: https://pnpm.io/installation

פתחו מסוף בתיקיית הפרויקט שהתקבלה מה־ZIP:

```bash
pnpm install --frozen-lockfile
pnpm run build
```

במחשב חדש בלבד, הפעילו את מיגרציית מסד הנתונים המקומי:

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_friendly_jocasta.sql
```

לאחר מכן הפעילו את המיגרציה החדשה:

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_many_abomination.sql
```

להוספת ניהול השירותים הפעילו גם:

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_chemical_diamondback.sql
```

להוספת מועדפים הפעילו גם:

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0003_steady_pestilence.sql
```

להוספת תיקים, צוות, סרטונים ותורים הפעילו גם:

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0004_awesome_ogun.sql
```

אין להריץ שוב מיגרציה על מסד שבו היא כבר הופעלה. הפעילו רק מיגרציות שחסרות במסד המקומי, לפי הסדר. `0001`–`0004` שומרות על התוכניות והרישומים הקיימים.

```bash
pnpm run dev
```

פתחו http://localhost:5173 לפי הכתובת המודפסת במסוף. בפיתוח מקומי על loopback בלבד, לחיצה על ״התחברות״ משתמשת בחשבון בדיקה של תשתית הפיתוח. נתוני הבדיקה נשמרים במחשב תחת `.wrangler/state`, ולא מועתקים לאתר החי. פרטי המנגנון: `build/sites-vite-plugin.ts`.

להדמיית גרסת הייצור, לאחר בנייה, הריצו `pnpm run start`. זה מפעיל שרת מקומי; אינו מפרסם. בסביבה זו אין כניסת בדיקה אוטומטית, ולכן API מוגן יחזיר 401 ללא תשתית זיהוי מהימנה. רישום service worker מופעל רק בבניית production ובהקשר מאובטח (HTTPS או localhost).

## התקנה בטלפון

היכנסו לאתר באותו חשבון בעל הרשאת גישה ובחרו בכפתור הטלפון שבכותרת:

- Android: פתחו ב־Chrome ובחרו התקנת אפליקציה או הוספה למסך הבית, אם הדפדפן מציג זאת.
- iPhone / iPad: פתחו ב־Safari, לחצו שיתוף ובחרו הוסף למסך הבית.

המועדפים, התוכנית ושמירת האימונים דורשים אינטרנט. במצב ללא חיבור מופיע מסך כללי בלבד. מידע מה־API, תוכניות, אימונים ועמודי כניסה אינם נשמרים ב־CacheStorage. תגובות API מוגדרות `private, no-store`.

האתר כרגע ציבורי; שמירת תוכניות ואימונים דורשת התחברות והנתונים נפרדים לכל משתמש. ניהול השירותים דורש גם הרשאת צוות. התקנה אינה משנה הרשאות גישה. לא בוצעה בדיקת התקנה על מכשיר iPhone או Android אמיתי; זמינות ההתקנה תלויה בדפדפן ובמדיניות המכשיר.

```bash
pnpm run typecheck

```

בדיקות ה־PWA מוודאות שמידות האייקונים תואמות ל־manifest, בקשות API וכניסה לא נשמרות, וניתוק רשת מחזיר רק מסך כללי. בדיקות האימון מפעילות SQLite בזיכרון עם המיגרציות האמיתיות ובודקות בידוד חשבונות, שמירת נתונים, מניעת אימון כפול, גרסאות מתנגשות והמשכיות אחרי טעינה. הן אינן תחליף לבדיקת התקנה במכשיר אמיתי. בדיקות SQLite דורשות Node התומך ב־node:sqlite; בסביבת הפיתוח נבדקו עם Node 24.

בדיקות המועדפים בודקות שמירה לאחר טעינה מחדש, הפרדה בין משתמשים, בקשות חוזרות, אימות קלט ושמירה על נתוני אימונים קיימים.

בדיקות השירותים בודקות הרשאות, הסתרת טיוטות, אימות קישורים ומחירים, שמירה וסתירות בין גרסאות. בדיקות התצוגה המקומיות אינן בדיקת הזמנה או גבייה אמיתית ב־Calendly.

## פרסום והזדהות

הגרסה הנוכחית בנויה ל־Sites ול־Cloudflare Workers עם D1, באמצעות React, TypeScript ו־Vinext. קובץ `.openai/hosting.json` מצביע על הפרויקט הקיים ומצהיר על bindings בשם `DB` ו־`BUCKET`. פרסום מתוך Sites מחיל את המיגרציות ומספק הזדהות, D1 ו־R2 לסרטונים.

הקוד תלוי בשער הזדהות מהימן שמנקה ומזריק את כותרות `oai-authenticated-user-*`. בפרסום אצל ספק אחר יש להחליף את `app/chatgpt-auth.ts` באימות session אמיתי ולהגדיר מסד D1 ואחסון R2 פרטי. **אין לקבל את כותרות הזיהוי ישירות ממשתמשי אינטרנט.** מנגנון כניסת הבדיקה המקומי אינו חלק מבניית הייצור.

לא מצורפים סודות, קבצי סביבה, מסדי משתמשים, `node_modules`, תיקיית Git או פלטי build. יש להריץ התקנת תלויות ובנייה לאחר החילוץ. הזכויות בתלויות צד שלישי נשארות לפי רישיונותיהן.

## הפעלת ניהול שירותים

בחרו ״כניסת צוות״ בתפריט והתחברו. חשבונות מורשים יראו גם ״ניהול שירותים״ בניווט.

המשתנה `DOCTORCOACH_ADMIN_EMAILS` מוגדר בצד השרת ב־Sites כמחרוזת כתובות דוא״ל מופרדות בפסיקים. רשימת הניהול הראשונית הוגדרה לחשבון הבעלים בלבד. אפשר להוסיף את נדב כמאמן במסך ״הזמנות וצוות״ באמצעות כתובת החשבון שלו. ניהול תורים, שירותים והרשאות דורש בנוסף הוספה לרשימת המנהלים בשרת; בחירה בנדב כנותן שירות אינה מעניקה הרשאה. שינוי משתנה דורש פרסום גרסה כדי להיכנס לתוקף. אין לשים את הרשימה בקוד הלקוח או במשתנה `NEXT_PUBLIC_*`. משתנה חסר או ריק חוסם ניהול לכולם. הזהות מגיעה משער ההזדהות של Sites; שימוש ברשימה מחוץ לתשתית זו מחייב ספק זהות מהימן.

שלושת מצבי השירות הם:

- טיוטה: מופיעה רק לצוות.
- מוצג ללא זימון חיצוני: מופיע לקהל ואפשר לשלוח בקשה לאישור באתר, ללא קישור זימון פעיל. מחיר שלא אושר מסומן כמוצע.
- פתוח להזמנות: נדרשים מחיר מאושר וקישור HTTPS לאירוע ב־Calendly. המחיר נשמר באגורות כדי להימנע משגיאות עיגול במסד.

שינוי מחיר, משך, נותן שירות, אופן מפגש או קישור ביומן בטופס מבטל את אישור המחיר עד שהעורך מאשר מחדש. בדיקת הקישור בשרת מאשרת מבנה וכתובת מארח בלבד; הצוות חייב לפתוח אותו ולוודא שהאירוע פעיל ושפרטיו תואמים. אין אימות זמינות ביומן החיצוני, Webhook או סנכרון הזמנות. תורים שאושרו בתוך DoctorCoach נבדקים לחפיפה מול אותו נותן שירות. אימות תשלומים והחזרים מתבצע ידנית ורק על ידי מנהל. אין מידע רפואי שמצורף לקישור.

השמירה בודקת את מספר הגרסה, כך ששתי עריכות במקביל אינן דורסות זו את זו. במקרה של סתירה הערכים נשארים בטופס ואפשר לטעון במפורש את הגרסה שבמסד. שלושת השירותים המקוריים נשארים כברירות מחדל מוצעות עד עריכתם הראשונה, ללא כתיבה אוטומטית בעת קריאה. העברתם לטיוטה מסתירה אותם גם לאחר רענון.

בתחילת אימון נשמר עותק של התוכנית, כולל מינונים והערות. עריכת התוכנית בהמשך אינה משנה אימון שכבר התחיל. ניתן להחזיק אימון פעיל אחד לחשבון; טעינה מחודשת מחזירה את הביצועים שנשמרו. שינוי מספרים בשורת סט דורש לחיצה על ״שמירת שינוי״ או ״סימון בוצע״. אין טיימר מנוחה, לפי האפיון המעודכן.

סיום אימון מחייב לפחות סט מסומן אחד; אימון חלקי נשמר עם מספר הסטים שבוצעו בפועל. סיום כפול מחזיר את אותו אימון. שינוי מגרסה ישנה של האימון נדחה, והמסך מקבל את הגרסה השמורה כדי לא לדרוס ביצוע ממכשיר אחר. רשומות היסטוריות אינן משתנות בעקבות הסרת תרגיל מהתוכנית.

ההיסטוריה והייצוא מציגים עד 50 אימונים מפורטים אחרונים. מדדי הסיכום מחושבים מכל האימונים המפורטים; רישומים מהגרסה הקודמת מוצגים בנפרד. משך האימון מחושב מההתחלה לסיום, כולל הפסקות. אלו נתוני ביצוע ודיווח עצמי, ללא הסקת אבחנה רפואית.


## הפעלה ראשונה של סביבת הצוות

1. התחברו בחשבון הבעלים ובחרו ״אזור המאמנים והצוות״.
2. בלשונית ״הזמנות וצוות״ הוסיפו את כתובת החשבון המדויקת של נדב בתפקיד מאמן. אין צורך למסור סיסמה. הקצאת תפקיד רופא נעשית בידי מנהל בלבד.
3. בחרו את אנשי הצוות הרלוונטיים וצרו קוד הזמנה. העבירו את הקוד למתאמן בדרך המתאימה לכם; האתר אינו שולח אותו אוטומטית. הקוד תקף לשבעה ימים ולחשבון מתאמן אחד.
4. המתאמן מתחבר, ממלא את שאלון הפתיחה ובודק את הקוד ב״הצוות שלי״. השיתוף מופעל רק לאחר אישורו ומציג למי ניתנת גישה ולאיזה מידע.
5. פתחו את התיק שהצטרף, שייכו תוכנית והוסיפו הנחיות. המתאמן יכול לאמץ את התוכנית, לשלוח דיווח שבועי ולבקש משוב על סרטון.
6. ב״סרטוני הדרכה״ העלו MP4 או WebM אמיתי ובחרו תרגיל. כל סרטון מתחיל כטיוטה. אישור זכויות ופרסום הופכים אותו לציבורי, כולל עמוד התרגיל. אין סרטונים מצולמים כלולים בקוד.
7. ב״ניהול שירותים״ אשרו מחירים, משכי מפגש ונותני שירות, הזינו קישור תשלום מאובטח בשקלים ותנאים מתאימים, ובמידת הצורך קישור Calendly. ודאו אצל הספק שהמטבע והסכום תואמים; האתר אינו בודק את עמוד התשלום החיצוני.
8. ב״ניהול תורים״ אשרו בקשות ומועדים, והוסיפו קישור למפגש או להוראות הגעה. שעון קיץ/חורף מחושב לפי התאריך בישראל. לאחר בדיקת עסקה אצל ספק הסליקה, עדכנו אסמכתא ואמתו תשלום. סימון החזר באתר מתעד החזר שכבר בוצע אצל הספק; אינו מבצע אותו.

המשתנה הסודי `DOCTORCOACH_CLINICIAN_EMAILS` מגדיר חשבונות רופא ראשוניים; בחשבון המארח הנוכחי הוגדר בעל האתר. הרשאות מאמן ורופא נוספות נשמרות במסד ומנוהלות בממשק. `DOCTORCOACH_ADMIN_EMAILS` שולט בניהול השירותים, התורים והרשאות הצוות. שניהם נבדקים בצד השרת לפי זהות מהימנה. תפקיד רופא לבדו אינו מספיק לקריאת תיק: נדרש גם שיתוף מתאים מהמתאמן. קידום מאמן לרופא אינו מרחיב את השיתוף הרפואי הקיים; נדרש אישור הזמנה חדש.

## נתונים, סרטונים ותזכורות

השדות הרפואיים והערות מסוג ״רפואי״ אינם מוחזרים כלל למאמן. מאמן משויך יכול לראות מטרות, נתוני אימון, דיווחי כאב ותפקוד וסרטוני ביצוע כפי שמפורט בהסכמת השיתוף. המתאמן רואה רק הערות מקצועיות שסומנו לשיתוף עמו. ניתוק איש צוות חוסם קריאות עתידיות לתיק ולסרטונים; אינו מוחק נתונים או עותקים שכבר נצפו.

קבצים נשמרים באחסון R2 פרטי; כתובת לצפייה עוברת דרך API שבודק הרשאות בכל בקשה ומחזיר `private, no-store`. אין קישור ציבורי לקובץ ביצוע פרטי. מגבלת קובץ היא 25 MiB, עד 30 סרטוני ביצוע או 300 סרטוני הדגמה לבעל החשבון. ניתן למחוק סרטונים שהעליתם. וידאו מתקבל רק בפורמט MP4/WebM עם בדיקת סוג, גודל וחתימה; זו אינה בדיקת אבטחה או התאמה מקצועית של תוכן הסרטון. הסרטונים אינם זמינים ללא חיבור.

כל דיווח שבועי נשלח פעם אחת לשבוע לפי שעון ישראל. התוכנית המשויכת מחליפה את התוכנית האישית רק לאחר אישור המתאמן; היא אינה משנה אימון שכבר החל או את ההיסטוריה. שמירות השאלון והתורים כוללות בדיקת גרסה למניעת דריסה מעריכה מקבילה.

תזכורות היומן דורשות שהמתאמן ייבא את קובץ ה־ICS ליומן ויאפשר התראות בו. הקובץ מכיל כותרת כללית וזמנים, ללא פרטי טיפול, שם לקוח או קישור למפגש. שינוי תור או ביטול אינו מסתנכרן אוטומטית ליומן שכבר יובא. המשתמש צריך לעדכן גם אותו.
